# Contributing to OpenMCU Cube

Thanks for taking the time to contribute! 🎉

This project is a single-file web application, so the contribution workflow is
deliberately light — but a few ground rules keep the repository clean.

## Code of conduct

Be respectful and constructive. This project has contributors from all over the
world; keep discussions in English and focus on the technical content.

## Reporting issues

Before opening an issue:

- Search [existing issues](https://github.com/mrz-ir/OpenMCU-Cube/issues) to avoid duplicates.
- Tell us which **version** (see the badge in the top bar), **device/package** and
  **browser** you used, plus the steps to reproduce.

A good issue looks like:

```
**Version:** 1.5.7
**Device:** HK32F103 LQFP48
**Browser:** Chrome 126 (Windows)

**Steps to reproduce:**
1. Open Clock Configuration
2. Enable HSE, set SYSCLK source to PLL
3. ...

**Expected:** ...
**Actual:** ...
```

## Suggesting features

Open an issue with the **Feature request** template. A short description of the
use case helps a lot — e.g. "support the PY32F002B SOP14 package" is clearer with
"…so I can generate code for my breakout board".

## Submitting changes (pull requests)

1. **Fork** the repository and create a branch: `git checkout -b fix/clock-labels`.
2. Make your change **directly in `OpenMCU_Cube1_5_7.html`** (there is no build step).
3. **Update the version number** in the file if the change is user-visible:
   - the `v1.x.y` badge in the top bar (both static HTML and the JS `setTimeout`
     badge updates),
   - the `document.title`,
   - generated-code headers (`/* Generated by OpenMCU Cube … */`, ZIP README, `.uvprojx` header).
4. **Add a `CHANGELOG.md` entry** under a new `## [Unreleased]` section (or the next version).
5. **Test** — see the checklist below.
6. Open a pull request describing what changed and why. Reference any related issue.

> ⚠️ The file also contains a few *historical* comments mentioning older versions
> (e.g. `v1.5.6 — Keil (.uvprojx) build fix`). Do **not** bump those — they document
> what was done in that specific version.

## Where things live inside the file

The app is one file, but the code is organized in clearly-marked sections:

| Section (search for) | Contents |
|----------------------|----------|
| `const SERIES = {` | Device database: label, max clock, HSI options, HSE/LSE pins, APB bus/peripheral lists |
| `const AF_F030`, `AF_HKF0301M`, … | Alternate-function tables per family |
| `PERIPH_META` / `PERIPH_ORDER` | Peripheral metadata and ordering |
| `renderPinout()` | Package/SVG drawing and pin coloring |
| `renderClockDiagram()` | Clock tree block diagram |
| `genPortPins()`, `buildZip()` | Code generation and ZIP building |
| appended `(function(){…})()` blocks | Version-specific patches — keep them at the end, don't rewrite history |

When you touch device data, **cross-check against the official datasheet** and
note the source in the commit message.

## Testing checklist

Before submitting, please verify at least:

- [ ] **All devices** render without JavaScript errors: switch the device dropdown
      through every option and open each tab.
- [ ] **Clock Configuration** diagram has no overlapping labels and no lines drawn
      over boxes (check the bottom peripheral-bus area).
- [ ] **Both themes** (dark/light) — labels readable, active clock path clearly visible.
- [ ] **Mobile width** (~390 px) — header shows the logo above the menu; tabs usable.
- [ ] **Code generation** produces valid `main.c` for at least one PY32 and one HK device.
- [ ] **Download ZIP** opens correctly (it must contain drivers + startup, not headers only).
- [ ] **Upload/restore** — a downloaded ZIP re-imports pins and clock settings.

## Release process

1. Update the version in the file (see above) and `CHANGELOG.md`.
2. Run the testing checklist.
3. Tag the release: `git tag v1.5.8 && git push --tags`.
4. Create a **GitHub Release** and attach the HTML file as an asset.
5. (Optional) if GitHub Pages is enabled, the new version goes live automatically
   once merged to `main`.
